# 涉外版报批资料上传

本分支只用于文化和旅游市场企业端 `whsq.mr.mct.gov.cn` 的“营业性演出（涉外/涉港澳台）”。不得进入浙江政务服务网国内事项，也不得使用国内的材料页或节目整格名称；申报主体与国内统一，网页和材料规则仍独立。

## 上传前与网页守门

1. 出现外国、香港、澳门或台湾演员，或事项明确为涉外/涉港澳台时使用本分支；混合演员项目也走涉外。
2. 按 [handoff.md](handoff.md) 生成/迁移唯一 JSON，通过 `--stage materials` 后设置 `ready_for_portal_check: true`。结构检查通过不代表材料就绪。
3. 每次打开新浏览器会话、切换账号、草稿或业务时，先重置 `ready_for_upload` 和 `runtime_qa`。当前 host、页面标记和业务名称与 JSON 的 `portal` 一致后才继续只读核对。
4. 核对目标演出名称/草稿，盘点页面已有演员、节目、场次和附件；完全一致的跳过，缺项才补，冲突停止。核对账号企业认证和实际草稿主体必须等于主体配置及 `application.applicant_entity.value`（配置中的统一主体）；表单不显示主体时从企业信息/草稿详情取证，不能跳过。材料仍为旧主体时先解决正文与委托关系冲突，不得改已签章文件。
5. 材料侧与当前会话门禁均通过、`warnings` 为空后，才设 `ready_for_upload: true`，再按 handoff 的 `--stage upload` 校验当前上下文后开始录入。

## 基本信息

1. 按 JSON 填演出类型、演出名称、演出起止日期、主要国别/地区、观众人数范围和办理人。
2. 本工作流默认入境为首演日前 10 天、出境为末演日后 10 天（项目默认值，不是法律规定）；必须做真实日期运算，能跨月、跨年。记录 `entry_exit_basis: computed_10_days` 和计算来源。
3. 正式材料明确给出其他入出境日期时以材料为准，记录 `entry_exit_basis: material_explicit`；与前后 10 天不同不自动判错，但必须有来源。
4. 日期选择后逐项读取年月日复核，不以翻月次数或视觉位置代替验证。

## 演员

1. 非内地演员选择“个体演员（非内地）”；混合项目中的中国内地演员选择“个体演员（内地）”。
2. 按 `performers[].sequence` 填姓名、性别、职务、国家/地区、证件类型/号码、证件有效期和出生日期。
3. “个人身份证明”上传姓名匹配的最终图片或 PDF；“演出协议/同意函件”上传对应已签名/盖章材料。
4. 网页不接受原始 DOCX 时生成派生 PDF，保留原件，并记录 `derived_from`、转换方式、新文件大小和 SHA-256；逐页渲染检查姓名、页数和可读性后才能就绪。
5. 保存后确认列表人数增加、本行字段和文件名正确，再处理下一人。已有同一姓名和证件类型的行先核对，不重复新增。

## 节目

1. 严格按 `programs[].sequence` 新增；页面节目名称取 `title.value`，不含文件名前序号。不得填国内节目单的“整格名称-演员名单”格式。
2. 节目类型按材料与页面选项映射。原值存 `source_value`，页面值存 `value`，无法完全对应时写 `mapping_reason`；不能静默改成“流行乐”或其他近似值。
3. `programs[].upload_order` 是唯一附件顺序。每个附件明确 `kind`：`per_song_lyrics`、`audio`、`video` 或 `total_lyrics`。常规单曲通常为本曲歌词 DOCX → 本曲 MP3 → 指定本曲 MP4，但具体仍以 JSON 为准。
4. 总歌词全项目恰好一次，`kind: total_lyrics` 只能属于 `programs[0]`；后续节目不得上传。
5. 同一视频在同一节目只上传一次。选择文件前以 `upload_id`、页面文件名和大小去重；自动化超时先查看页面状态，不能直接二次选择。
6. 去掉序号与扩展名后，歌词、音频、视频的节目主名称必须与 `title` 对应；大小写、空格、括号或译名冲突时停止。
7. 保存后确认节目总数增加、附件文件名与大小齐全，再进入下一首。

## 场所与场次

1. 按实际材料选择歌舞娱乐场所、酒吧/饭店等非演出场所、演出场所或临时搭建场地；不同类型的动态槽位不能互套。把是否需要消防及证据记录到 `venue.fire_safety_requirement`，不清楚时先只读核对页面。
2. 先选择/填写场所并等待场所字段稳定，再上传场所证明和消防安全证明，最后填写场次。选择已有场所或上传附件可能重置尚未保存的时间；因此场次必须最后填写并逐项读取复核。
3. 场所证明上传对应最终场地同意材料，两个槽位不能互换。“消防安全证明”使用经核实适用于本场地的本地文件；公开版不附任何固定消防资产。填写文件路径、大小、SHA-256 与实际归属，核对正文、场地、单位和有效性；仅在对应槽位上传，不可替代场所同意材料。若自行配置 skill_asset，须在本地主体配置的 asset_pins 登记同一资源的 hash、大小、槽位和分支。
4. 固定消防材料在项目 JSON 中使用 `upload_method: skill_asset`，并记录 `asset_path`、文件名、大小、SHA-256 和稳定 `upload_id`；不得要求每个项目重复复制该 PDF，也不得从历史项目临时借用路径。
5. 录入场所名称、省/市/区、详细地址、每场日期、开始/结束时间和申报场次数。
6. 弹窗打开时已经存在的第一行就是第一场。单场项目绝对不要点击“增加演出场次”；只有需要第二场及以后时，才按“目标场次数 - 当前可见行数”点击。不得先填写第一行再点击一次按钮来“确认”第一场。
7. 保存前确定性校验：开始时间输入框数量 = 结束时间输入框数量 = 场次明细行数 = `declared_session_count`；单场时应各为 1；不以是否出现“删除”按钮作为场次数证据。逐行读取完整日期、开始时间和结束时间，确认无空行、无重复行，再填“演出场次数”。
8. 以弹窗关闭和外层场次卡片出现为保存成功；外层卡片的日期范围和场次数必须与 JSON 一致。外层不显示具体时刻或消防附件时，以保存前已读取的精确字段值为依据，必要时重新打开弹窗只读核对后关闭；不得靠重复保存、重复增加场次或重传附件验证。

## 提交前核验与停止点

- 当前网站、业务、草稿仍属于涉外分支；没有借用国内网页、槽位或主体判断。
- 入出境日期符合 JSON 的 `entry_exit_basis`；演出日期、观众人数和办理人正确。
- 页面演员、节目和场次数量与 JSON 完全一致，无重复、无缺项。
- 每曲歌词/音频及指定视频齐全；每个视频一次；总歌词仅第一首一次。
- 场所证明与固定消防证明未互换；场次明细行数、每行日期时间与申报次数严格一致，单场未点击“增加演出场次”。
- 所有慢速上传均显示精确文件名、大小且遮罩消失；没有因等待超时重复上传。
- 保存草稿并复核；无最终提交授权时停在“确认以上承诺”之前。已有明确提交授权则核验后继续，不重复请求。
