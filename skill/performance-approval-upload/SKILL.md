# 报批资料上传

## 先确定主体和分支

国内与涉外统一使用 [申报主体配置](assets/config/applicant-policy.example.json) 中的 `applicant_policy.legal_name`。材料、账号企业认证信息和实际草稿主体必须逐字一致；即使涉外表单不显示主体，也须到账号/企业信息或草稿详情核对，无法证明则不写入。场地运营方、消防材料所属单位和实际场所仍按材料分别记录。

旧 JSON、申请表、许可证或委托书若使用另一主体，记录主体冲突、撤销就绪状态并先修正源材料。不得只改 JSON 掩盖冲突，不得改写已签名/盖章文件；需重新出具或补签的材料应列明，其他可完成工作继续。公开安装版配置为空时先配置实际主体，不采用历史案例默认值。

- **国内**：全部演员为中国内地人员；`recept.zjzwfw.gov.cn`，事项“举办内地文艺表演团体、个人参加的营业性演出审批”。只读 [国内步骤](references/domestic.md)。
- **涉外**：含外国、香港、澳门或台湾演员（含混合项目）；`whsq.mr.mct.gov.cn`，业务“营业性演出（涉外/涉港澳台）”。只读 [涉外步骤](references/foreign.md)。
- 演员身份、JSON 分支、host 和当前事项必须相符；冲突时先查材料和页面，不能仅凭目录名或页面标题强行选路。比较分支时才读 [差异表](references/branch-matrix.md)。

## 执行入口

1. 按 [数据交接](references/handoff.md) 查找唯一 `报批上传数据.json`。缺失时从对应模板生成；旧结构按交接文档迁移并保留原始副本。
2. 运行 `python3 scripts/validate_upload_data.py /绝对路径/报批上传数据.json --stage materials`；修复内容、文件和主体冲突，完成正文/签章核验后才录入或上传。页面槽位或材料要求不明时可先只读核对网页。结构检查 `--stage schema` 只用于模板开发，绝不表示可上传。
3. 通过当前可用的浏览器控制能力定位用户已登录页面；优先语义定位，按实时页面调整步骤。读取当前账号、事项、草稿及已有对象，核对后记录本次 `runtime_qa`，再运行交接文档的 `--stage upload` 校验。历史布尔值、校验器通过和已登录本身均不代替当前页面证据。
4. 逐项录入、上传、保存并读取持久化结果。`semantic_type` 表示数据含义，`target_field` 表示页面槽位；不要将含义相近的字段或文件互换。
5. 完成后按分支清单核对数量、顺序、主体、日期和附件，报告草稿/提交状态及剩余阻塞。用户已有明确最终提交授权时完成核验后继续；只有授权缺失时才停在承诺或最终提交前，不重复索要已给出的授权。

## 恢复、去重和有界等待

- 以对象 `stable_key` 和当前实际字段对账：完全一致跳过，缺项补齐，冲突保留草稿并处理原因。附件用精确 `target_key`、SHA-256 和 `upload_id`；远端不能读 hash 时，核对文件名、大小、槽位、完成状态及本地执行记录，不声称已比较远端 hash。
- 上传前盘点当前窗口；状态不明时只观察，不能再次选择文件来探测成功。每 15–60 秒读取一次进度，连续 3 次无变化后最多每 60 秒检查；默认累计 15 分钟仍不明则保存可用草稿、记录待核验项并返回。只有明确失败且确认未生成附件后，才允许一次重试；再次失败就报告。用户给定其他等待预算时采用该预算。
- 新会话、换账号/草稿/事项或材料变化，立即撤销网页就绪记录。保存后无持久化证据的对象保留为“待核验”；不能因为弹窗关闭或一次工具超时重复新增。
- 身份证件号、护照号、联系方式和原始账号信息仅用于本地材料与网页填写，不写入技能、测试、发布包、日志或聊天总结。项目 JSON 和运行记录只存项目本地。
